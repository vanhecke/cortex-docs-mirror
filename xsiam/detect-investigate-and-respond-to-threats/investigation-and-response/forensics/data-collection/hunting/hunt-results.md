# Hunt results

The hunt results page consolidates information collected by the Cortex XDR agent enabling you to investigate and take action on your endpoints.

### Review process execution search results

The **Process Execution** table displays a normalized table containing an overview of all of the different process execution artifacts collected from the endpoints. Investigate the following detailed fields:

{% hint style="info" %}
The grouping button (![forensics-grouping-button-icon.png](https://2786854933-files.gitbook.io/~/files/v0/b/gitbook-x-prod.appspot.com/o/spaces%2FAEIjuYE3RXcIfmuQnBbm%2Fuploads%2Fgit-blob-0ff16e50ac88299e0da6d60544ae1f96e269ead5%2F0125365634a8ff21f09dcdff46fa71c29b6c5354ae6d14e0fce4a01f4ea002f4.png?alt=media)) shows the number of affected endpoints grouped by executable name. This enables you to perform hunting via frequency analysis (referred to as stacking) and provides a birds eye view of potential malware files that require further analysis.
{% endhint %}

<table><thead><tr><th width="156">Field</th><th>Description</th></tr></thead><tbody><tr><td>Context</td><td>Contextual details relating to the executed process such as files opened, command line arguments, or process run count.</td></tr><tr><td>Executable Name</td><td>Name of the executable.</td></tr><tr><td>Executable Path</td><td>Path of the executable.</td></tr><tr><td>Hostname</td><td>Name of the host on which the process resided.</td></tr><tr><td>MDS</td><td>MDS value of the executable file, if available on the file system.</td></tr><tr><td>SHA1</td><td>SHA1 value of the executable file, if available on the file system.</td></tr><tr><td>SHA256</td><td>SHA256 value of the executable file, if available on the file system.</td></tr><tr><td>Timestamp</td><td>Timestamp associated with the executable file or process execution.</td></tr><tr><td>Type</td><td>Type of process artifact.</td></tr><tr><td>User</td><td>User name associated with the execution artifact.</td></tr><tr><td>Verdict</td><td><p>WildFire verdict for the following process execution artifacts.</p><ul><li>Prefetch</li><li>Recentfilecache</li><li>Shimcache</li><li>UserAssist</li></ul><p>If there is a WildFire verdict, the relevant <strong>Verdict</strong> is displayed.</p><ul><li>Unknown</li><li>Benign</li><li>Malware</li><li>Grayware</li></ul><p>Also, a link to the WildFire analysis report is available for review.</p></td></tr></tbody></table>

### Linux

The collection results for the **Core Linux** artifacts include information about each artifact.

<table><thead><tr><th width="161">Artifact</th><th>Result Details</th></tr></thead><tbody><tr><td>Auditd Rules</td><td><strong>Auditd Rules</strong> artifact in Linux forensics refers to the log data collected by the Linux Audit Daemon, a core component of security auditing. It records a detailed, chronological trail of system events based on a set of pre-configured rules.</td></tr><tr><td>Authorized Keys</td><td>Shows the public keys that are permitted to log in as a specific user via SSH. Attackers can add their own keys to this file to gain persistent access to a system.</td></tr><tr><td>Environment Variables</td><td>Lists environment variables for a given context (for example: a user's shell or a specific process). These variables define the execution environment and can contain important paths, configurations, or sensitive data.</td></tr><tr><td>File Listing</td><td>Shows information about the timeline of file system activity.</td></tr><tr><td>Files &#x26; Processes</td><td>Lists files opened by processes. This is crucial for mapping processes to the files and network sockets they are interacting with, which can reveal hidden activities, loaded libraries, or active network connections.</td></tr><tr><td>Firewall Rules</td><td>Lists control network traffic. Analyzing these rules is crucial for understanding the network security posture and identifying potentially malicious or overly permissive configurations.</td></tr><tr><td>System-Wide Configuration</td><td>Shows key-value pairs parsed from various configuration files in the <code>/etc</code> directory, for example: /<code>etc/resolv.conf</code> for DNS settings. This artifact helps understand the system's network and operational configuration.</td></tr><tr><td>Kernel Modules</td><td>Lists kernel modules on the system, their state, and the associated file path. Malicious actors may use custom kernel modules (rootkits) to hide their presence or gain privileged access.</td></tr><tr><td>Known Hosts</td><td>Lists the files that store the public keys of SSH servers a user has connected to. This helps to verify the server's identity and prevent man-in-the-middle attacks by alerting the user if the server's key changes.</td></tr><tr><td>Mounted Filesystems</td><td>Lists all mounted file systems, their sources (devices), types, and unique identifiers. This is useful for discovering connected storage and network shares, and understanding the file system layout.</td></tr><tr><td>Network Connections</td><td>Shows the lists of active network connections and listening ports. Essential for identifying unauthorized network communications, malware command and control (C2) channels, or unexpected listening services.</td></tr><tr><td>Running Processes</td><td>Shows a detailed snapshot of running processes on the system. This includes process identifiers, user context, executable path, parent-child relationships, state, and performance metrics. It is a cornerstone artifact for live system analysis.</td></tr><tr><td>System Information</td><td>Provides fundamental hardware and system information, including manufacturer, model, UUID, and memory details. This helps to identify and profile the system.</td></tr><tr><td>Systemd Service</td><td>Lists the system daemons or services (for example, from systemd). Analyzing these is key to understanding what long-running processes are configured on the system and to spot malicious or unnecessary services.</td></tr><tr><td>User Login &#x26; Session History</td><td>Shows records of user login sessions from the last command, showing who logged in, from where, and for how long. This is essential for auditing user access and investigating unauthorized logins.</td></tr></tbody></table>
